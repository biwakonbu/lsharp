# L# v0.2 Milestone 3 — Validation parity and artifact closure

## 目的

M2 で追加した intent/evidence graph と `lsharp validate` を、Rust の検証済み slice
から selfhost/native の日常開発経路へ移し、Mac Apple Silicon と Linux x86_64 で
同じ observable contract を閉じる。M3 は validation model を作り直す milestone では
なく、既存の version 1 manifest、report、exit code、provenance を全 surface に接続
するための parity / artifact milestone とする。

## タスク分解

### EC-M3-01 — canonical manifest parity

同じ source fixture と同じ version 1 manifest fixtureを Rust oracle、selfhost stage0、
native program で実行する。

- source node / evidence / edge の順序、stable ID、sampling、provenance の JSON bytes を
  canonical serializer と比較する。
- manifest input → report と source input → report の status、trace gap、diagnostic、exit
  codeを比較する。
- malformed schema、unknown field、duplicate node、orphan endpoint、逆順 spanを各入口で
  fail-closed にする。
- source の `:motivates` が未登録の intent node を参照する場合は stable code `5`、exit `1`、
  report/manifestなしで拒否することを native source-file smoke の contract に含める。
- source edge の endpoint が不足する malformed metadata は stable code `1`、exit `1`、
  report/manifestなしで拒否することを native source-file smoke の contract に含める。
- source edge の wire prefix が不正な endpoint は stable code `2`、exit `1`、report/manifestなしで
  拒否することを native source-file smoke の contract に含める。
- source metadata の kind と wire prefix が不一致な node は stable code `3`、exit `1`、
  report/manifestなしで拒否することを native source-file smoke の contract に含める。
- `supports` / `contradicts` が未登録 evidence を参照する source edge は stable code `6`、exit `1`、
  report/manifestなしで拒否することを native source-file smoke の contract に含める。
- review registry が存在する状態で未登録 review を `evaluates` / `invalidates` する source edge は
  stable code `10`、exit `1`、report/manifestなしで拒否することを native source-file smoke の
  contract に含める。
- source review registry が同じ ID を複数回宣言する場合は stable code `7`、exit `1`、
  report/manifestなしで拒否することを native source-file smoke の contract に含める。
- review metadata の visibility が `public` / `redacted` 以外の場合は stable code `8`、exit `1`、
  report/manifestなしで拒否することを native source-file smoke の contract に含める。
- `evaluates` / `invalidates` の review edge subject が review など許可されない kind の場合は

  stage0 の両方で同じ失敗値を固定する。

完了条件: bytes / report / exit code の差分がなく、fallback 呼び出しがないことを
evidence envelope で確認する。

### EC-M3-02 — selfhost `App.Cli` validation surface

`App.Cli` の `validate --source <file> --format json [--emit-manifest <path>]` を native
stage0 の正式入口にする。

- success (`unknown` を含む) では report stdout と manifest file を混ぜない。
- `--format text` は JSON と同じ facts を固定順で出力し、canonical fixture の unknown report は
  exit `2` であることを native source-file smoke の contract に含める。
- `--emit-manifest` の親ディレクトリが存在しない場合は、stable write diagnostic、exit `1`、
  report/artifact なしで fail-closed になることを native source-file smoke の contract に含める。
- complete graph（independent review あり）は JSON `status: pass` / exit `0` と同じ text facts を
  返すことを native source-file smoke の contract に含める。
- contradiction（independent review の `:outcome "contradicted"` と `:contradicts` edge）は
  JSON `status: fail` / exit `1` と同じ text facts を返し、stdout の report を保持して stderr は
  空にすることを native source-file smoke の contract に含める。
- invalidation された review と `evaluates` edge で stale になった evidence は、JSON/text とも
  `status: unknown` / exit `2`、`stale_reviews: 1`、`stale_evidence: 1` の report を stdout に
  返し、stderr を空にすることを native source-file smoke の contract に含める。
- parse/graph error では report/status/artifact を残さず exit `2`、manifest write error では
  stable diagnostic と exit `1` を返し report/artifact を残さない。
- output path の親ディレクトリ、symlink、既存 file、source fingerprint を明示的に検査する。
- `cargo`、`rustc`、host `lsharp`、暗黙の Rust fallback が成功経路に入らない negative gate
  を追加する。

### EC-M3-03 — `EmbeddedCli` parity / external boundary

`EmbeddedCli` が公開する command surface を `App.Cli` と同じ fixture で検査する。

- `validate` の source/report/manifest boundary と `pass=0` / `fail=1` / `unknown=2` を
  実 artifact から確認する。EmbeddedCli の Rust-host actual Wasm fixture では、source
  report の 3 status/exit boundary と、`--emit-manifest` の version 1 manifest file 出力を
  検証済み。manifest write failure では no-report/no-file と exit `1` の fail-closed も
  検証済み。
- native の atomic/durable filesystem、native write/provenance、component、MCP host
  integration は曖昧な成功にせず、未実装なら stable な external-boundary として返す。
- `tools/list` / `tools/call` の MCP inline manifest は Rust host contract として保持し、
  EmbeddedCli の filesystem writer は version 1 serializer を再利用する。atomic/durable と
  native provenance はこの task の完了条件に含めず、EC-M3-01/02 の後続境界として残す。

### EC-M3-04 — two-target artifact/runtime matrix

Mac Apple Silicon (`aarch64-apple-darwin`) と Linux x86_64 (`x86_64-unknown-linux-gnu`)
を別々の evidence lane として閉じる。

- Mac: `scripts/ci/native-selfhost-dev-source-file-smoke.sh` と release-stage0 package。
- Linux: `scripts/ci/native-linux-x86-native-stage0-source-file-smoke.sh` と Lima VM gate。
- 各 target で `check` / `test` / `compile` / `build`、manifest bytes、Wasm validate、
  standalone runtime の結果を記録する。
- stage0 producer commit、source fingerprint、artifact digest、runtime target を同じ
  evidence envelope に保存する。stale artifact は採用しない。

### EC-M3-05 — provenance and rollback gate

日常開発の成功と release artifact の再現性を分離して検証する。

- stage0 の取得、再生成、source commit mismatch、rollback を fixture と script の contract
  に固定する。
- current source と stage0 source の fingerprint mismatch は実行前に拒否する。
- VM lock、artifact reuse、temporary workdir の cleanup を gate 後に確認する。
- rollback は emergency path として残し、Rust oracle の成功を native GREEN と数えない。

## 依存関係と実行順

```text
EC-M3-01 canonical parity
        ↓
EC-M3-02 App.Cli ──┐
                    ├─ EC-M3-04 two-target matrix
EC-M3-03 EmbeddedCli┘          ↓
                    EC-M3-05 provenance / rollback
```

各タスクは `RED → selfhost/native 実装 → focused GREEN → Rust differential → artifact /

Linux VM の heavy replay と同じ仮説の重複実行を禁止する。

## 完了ゲート

M3 の完了は単一の unit test、Rust driver の成功、summary/header、または stale artifact
では宣言しない。次の全項目を current checkout の証拠で監査する。

1. Rust oracle と native stage0 の source/manifest/report/exit code が同一 fixtureで一致する。
2. `App.Cli` と `EmbeddedCli` の対応 command、拒否境界、artifact bytes/runtime が確認できる。
3. Mac Apple Silicon と Linux x86_64 の必要 lane がそれぞれ pass する。
4. 成功経路に `cargo`、`rustc`、host `lsharp`、Rust fallback がないことを negative gate で確認する。
5. producer commit、source fingerprint、manifest/artifact digest、target、runtime の provenance

6. 検証済み evidence を ADR に移し、aggregate が未完了なら `TODO.md` の `[~]` を維持する。

# L# v0.2 Milestone 2 — Intent and evidence graph

## 目的

implementation conformance の pass を stakeholder intent の妥当性と混同せず、
intent、claim、前提、未決定事項、実行 evidence、review、provenance を追跡できる
構造を導入する。M2 は M1 の contract runner を置き換えず、別の validation 軸を
追加する。

## タスク分解

### EC-M2-01 — intent AST と stable ID

最初の slice は `lsharp-types::intent` に canonical node と ID wire contract を
追加済み。

- `Intent` / `Claim` / `Assumption` / `OpenQuestion` の typed node
- `IntentNode` による variant projection
- `kind:namespace/key` の cross-target stable ID と全 graph kind の wire parser
- source span / declaration order / Rust hash から identity を導出しないことの回帰テスト

残る acceptance は evidence を含む graph manifest 接続である。
ID 省略は自動命名せず fail-closed に拒否する方針を ADR で固定した。
source adapter の project 単位 duplicate ID 診断は、最初の宣言 span と重複宣言 span を返す
fail-closed 境界として接続済みである。`:intent` / `:claim` / `:assumption` /
`:open-question` の明示 wire node と Rust adapter、stable ID の wire 復元と typed kind mismatch の
fail-closed 検査は `StableId::parse` / typed ID `parse` と regression test で固定した。
wire identity、text、source span から 4 種類の typed AST node を作る
`IntentNode::from_wire_parts` も追加し、graph-only kind は暗黙に AST へ変換せず拒否する。
source の `motivates` / `constrained-by` / `tested-by` edge adapter と required-field evidence
record adapter は実装済みだが、selfhost/native parity は引き続き残件である。optional sampling fields は
source adapter から canonical plan へ投影し、`validate --source --emit-manifest` で version 1 file artifact
へ atomic/durable に出力する。`supports` / `contradicts` は登録済み evidence にだけ接続し、
registry 未接続時は明示的な入力エラーで拒否する。
selfhost `IntentSource` の node/edge consumer は tagged form 4要素と、それぞれ ID+本文、endpoint ID×2
の payload arity を厳密に要求し、内部 form に余分な値がある場合も span付き malformed として fail-closed にする
（parser/graph の上位 parity は残件）。4要素未満の malformed form も、存在する kind と offset を保持し、
欠落 offset のみ `-1` として診断を返す。

### EC-M2-02 — evidence graph

`IntentNode` の ID を subject として、次の edge と evidence を lossless に保持する。

最初の model slice は `lsharp-types::evidence` に実装済み。

- method/outcome/independence 付き `Evidence`
- runner/target/source commit/artifact digest を持つ `ExecutionIdentity`
- cases/seed/generator/shrinks/coverage を持つ `SamplingPlan`
- producer/tool version/timestamp を持つ `Provenance`
- typed edge と duplicate/missing evidence を検査する `EvidenceGraph`

- `motivates`, `constrained-by`, `tested-by`
- `supports`, `contradicts`, `evaluates`, `invalidates`
- method / outcome / runner / target / source commit / artifact digest
- provenance と independence (`same-author`, `independent-review`, `external-observation`)
- required な runner/target/source commit/artifact digest、generator、producer/tool version/timestamp
  は空値を許さず、`EvidenceGraph` 登録時に fail-closed で検査する。
- review endpoint には optional な registry record（opaque `provenance_digest` と
  `public` / `redacted` visibility）を追加できる。registry を明示した manifest は
  `evaluates` / `invalidates` の review ID を登録済みに限定し、author/email/body/URL/token は wire に持たない。

edge の両端 ID が同じ node kind に限定されるか、cross-kind を許すかを RED で
固定した。`IntentGraph` は node の duplicate ID、evidence の required field、typed
edge の evidence closure を fail-closed に検査する。graph manifest の deterministic
JSON projection と version 1 JSON manifest parser は M2-03 の library slice として追加済み。
source syntax の node registry、required-field evidence record、`motivates` / `constrained-by` /
`tested-by` / `evaluates` / `invalidates` edge 投入は Rust adapter へ接続済み。
`supports` / `contradicts` は `EvidenceId` と Claim endpoint、registry closure を検証し、
未登録時は `EvidenceRegistryRequired` として返す。optional
sampling fields の source→canonical→manifest 投影と Rust CLI の atomic/durable manifest emission は接続済みだが、実 edge の selfhost/native parity
は未完了である。
review registry の opaque provenance/redaction boundary は Rust manifest slice として接続済みだが、
provider/署名 authentication と source/selfhost/native producer は未完了である。

### EC-M2-03 — `lsharp validate`

graph の欠落・矛盾を fact として返す command surface を追加する。

判定 model、versioned JSON manifest parser、Rust CLI の最初の slice は実装済み。

- `IntentGraph::validate()` の trace gap / open question / independent review / contradiction 集計
- `pass` / `fail` / `unknown` の status と stable trace-gap code
- contradiction evidence の重複計上を抑止
- `ValidationReport::to_json_string()` の strict object projection（`verified` なし）
- `ValidationReport::to_text()` の deterministic fact projection

`App.Cli` と `EmbeddedCli` の `validate --source <file> --format json` source/report/exit
slice は同じ `unknown` / trace-gap contract を実 artifact で検証済みである。manifest input/
emission、native parity、MCP、両 supported target の証拠は未完了であり、EC-M2-03 は `[~]` を
維持する。

- trace gap、未回答 open question、独立 review 不足、contradicting observation
- text/JSON の同一 report schema
- conformance の `test` と intent validation の `validate` の exit code を分離
- top-level `verified` を生成しない

`lsharp validate [<manifest>] [--format text|json]` は parser → graph → `validate` → report
を接続し、`pass=0` / `fail=1` / `unknown=2` の exit code を返す。manifest を省略した場合は
project root の `lsharp.toml` にある `[validation].manifest` を project-relative に解決し、
絶対 path、`..`、存在しない file、project root 外の symlink を拒否する。source を直接検証する
`lsharp validate --source <source.ls> [--format text|json]` も Rust parser と source graph
adapter へ接続した。`--source` と manifest path は同時指定せず、source に contract/evidence が
なければ `unknown`、parse/adapter error は入力診断として返す。L# source syntax の
`supports` / `contradicts` は登録済み evidence に接続し、registry 未接続を明示的に入力エラーとして
返す。manifest emission は `--emit-manifest` で atomic/durable に接続済みで、Rust MCP の `lsharp_validate` source/file /
manifest/manifest_file → structured report と `include_manifest` inline artifact wiring も接続した。ただし selfhost/native parity、EmbeddedCli/MCP の
manifest emission wiring、
supported 2 targets の artifact/runtime evidence は残件である。source `tested-by` は claim trace を
接続するが、Contract の executable definition までは完了を意味しない。

## Gate

M2 完了は node unit test だけでは宣言しない。parser → graph → `validate` → text/JSON
report の実行、Rust/selfhost の stable ID parity、Mac Apple Silicon と Linux x86_64
の必要な native evidence を揃え、未接続の source syntax や external provenance は
残件として TODO に維持する。

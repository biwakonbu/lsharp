## 目的

L# 自身で source を編集し、型検査し、Wasm を生成・実行し、公開 tooling と package/release
boundary を同じ contract で検証できる状態を作る。各 task は狭い observable contract であり、
aggregate は一つの focused test や Rust host の成功では完了しない。

## 開始条件

- v0.3 の review provenance/lifecycle は `[~]` の残件を明示したまま維持する。
- current checkout に一致する native stage0 の source commit/fingerprint、manifest、取得証跡を確認する。
- parser/type/GC/release の active worktree と ownership が重ならない taskを選ぶ。
- Linux replay lock が live の場合は VM を重複起動せず、Mac/focused/docs sliceだけを進める。

## Observable task backlog

### V4-M1-01 — semantic fixture matrix

**契約:** 一つの fixture set を Rust oracle、Rust-host selfhost、Mac native stage0、Linux native
stage0へ渡し、AST/type/IR/Wasm/runtime/report の比較対象と failure boundary を機械的に列挙する。

- RED: parser、type、record/ADT/pattern、module/import、GC/I/O、public command の代表 fixture と
  invalid fixture を inventory 化し、各 fixture の期待 code/span/exit/artifact/runtime を固定する。
- GREEN: `scripts/ci` の fixture manifest と差分比較 helper を追加し、fixtureごとの未接続 boundary を
  `[~]` として出す。未知の fallback、stale stage0、target未指定は失敗にする。
- Gate: Rust focused test、native stage0 check、必要な Wasm validate/runtime、Mac/Linux evidence。
- 依存: v0.3 identity field order、current stage0 provenance。

**現在の verified slice (2026-08-01):**

- version 1 manifest は source path、valid/invalid kind、diagnostic code/span、exit code、artifact/runtime
  の pending/not-run 状態、observable layer、commands、両対応 target を必須化する。
- artifact を要求する fixture は `compile` または `build` を commands に含める。`check` だけで
  artifact/runtime boundary を宣言できないことを validator の verified slice として固定した。
- artifact/runtime を要求する fixture は、それぞれ `codegen`/`wasm`、`runtime`/`runtime` の
  layer・observable 対を持つことを validator の verified slice として固定した。失敗する
  intermediate codegen fixture は artifact を要求せず、runtime `not-run` と整合する。
- validator は project 外 source、未知 target、fixtureごとの target 不一致、暗黙 fallback/network、
  valid/invalid と diagnostic の矛盾を fail closed にする。
- diff helper は同一 source commit の Rust oracle/native-stage0 report を target 単位で比較し、
  `pass` (0)、`mismatch` (1)、`pending` (2) を分ける。artifact/runtime が pending のままなら成功扱いにしない。
- Rust oracle producer は compiler と Wasmtime の絶対パス、source commit、target、work directory を
  caller から受け取り、反復可能な `--fixture-id` で選択した fixture set を決定的な ID 順に
  compile → Wasm artifact → runtime へ渡し、valid/no-diagnostic fixture と、Rust 診断に明示的な
  `LS####` code と byte span がある invalid fixture の report を一つにまとめる。複数 fixture の
  場合は各 fixture を `<work-dir>/0000/` のような固有の作業ディレクトリへ隔離し、単一 fixture
  の既存 artifact path (`<work-dir>/semantic-fixture.wasm`) は互換維持する。重複 ID は拒否する。
  `LSHARP_DISABLE_EMBEDDED_COMPONENT=1` を設定し、embedded selfhost fallback を使わない。
- invalid report は code/span が両方得られる場合だけ line/column へ変換し、lexer/parser の code 欠落や
  module error の span 欠落を synthetic な診断で補完せず fail closed にする。これは producer の
  focused contract test で検証済みだが、実際の Rust/native 実行、Wasm digest、runtime output、
  Linux VM evidence、native-stage0 counterpart、全 fixture matrix はまだ未検証である。
- native-stage0 producer は stage0 manifest の kind/target/source commit と、明示した native runner・
  Wasmtime・work directory を検証し、反復可能な `--fixture-id` で選択した fixture set の valid
  artifact/runtime と explicit invalid code/span を一つの report にまとめる。複数 fixture の場合は
  各 fixture を固有の work directory へ隔離し、単一 fixture の既存 artifact path は互換維持する。
  runner の実行環境から `LSHARP_PATH` と embedded fallback flag を除去し、code/span が欠ける
  invalid output や重複 ID は拒否する focused contract test まで検証済みである。
  ただし実 stage0
  package、Mac/Linux target、Wasm validation/runtime、native/Rust differential は未接続である。
  したがって V4-M1-01 全体は `[~]` のまま保持する。
- 決定記録: [`v0.4 M1-01 fixture matrix ADR`](../../adr/decisions-v0.4-m1-01-semantic-fixture-matrix.md)。

### V4-M1-02 — compiler pipeline / module graph closure

**契約:** multi-file source の module/import/open/qualified/private と SCC inference/cache が、
`check → compile → build` の全経路で deterministic な module order、diagnostic/span、artifact bytes を返す。

- RED: import cycle、private export、missing module、record/ADT cross-module、cache stale の fixture を固定する。
- GREEN: parser/type/lowering/linker の境界ごとに explicit diagnostic を返し、Formatter 特例や
  Rust-only module resolver を成功経路から外す。
- Gate: Rust differential、native Mac、Linux x86_64 source-file compile、Wasm standalone runtime、
  cache hit/miss evidence。
- 依存: V4-M1-01、既存 `LEGACY-MODULE-01` / `LEGACY-COMP-01`。
- 設計記録: [`v0.4 M1-02 module graph and cache evidence contract`](../../adr/decisions-v0.4-m1-02-module-graph-contract.md)。
- 実装済み部分は `imp-04-module-system-strengthening` に記録された Rust SCC/cache slice として扱い、
  V4 の native Mac/Linux、Wasm/runtime、fixture/report parity が揃うまで `[~]` を維持する。

### V4-M1-03 — execution semantics / memory ABI closure

**契約:** record/ADT/pattern/Map/closure、GC root/free-list、linear-memory ABI、argv/file/stdin が、
lowering → codegen → runtime で同じ observable result と resource failure code を返す。

- RED: nested pattern、constructor refinement、large record/Map、closure capture、allocating helperを
 跨ぐ root、4096-byte boundary、fd error、GC limit の fixtureを固定する。
- GREEN: unsupported representation は明示拒否し、実装済み slice は source/ftable/import、Wasm bytes、
  runtime output、memory/GC metrics まで接続する。
- Gate: focused Rust oracle、native stage0、Wasm validation/runtime、Mac/Linux target matrix、negative
  no-fallback gate。
- 依存: V4-M1-01、既存 `LEGACY-LANG-01/02`、`LEGACY-IO-01`、`LEGACY-RUNTIME-01`、`LEGACY-ROOT-01`。
- 設計記録: [`v0.4 M1-03 execution semantics and memory ABI contract`](../../adr/decisions-v0.4-m1-03-execution-semantics-contract.md)。
- task 分解: `V4-M1-03-R1` value representation、`R2` closure/allocation、`R3` GC/free-list、
  `R4` linear-memory/I/O ABI、`R5` evidence projection。resource/ABI observation の schema 拡張と
  native/runtime/two-target evidence が揃うまで `[~]` を維持する。
- **R1 verified partial (2026-08-01):** `valid/nested-record-pattern` を matrix に追加し、nested
  record variable pattern の AST/type/IR/ftable/import/Wasm/runtime/report 観測項目を契約へ列挙した。
  matrix 6 tests、Rust oracle fixture implementation commit `4790bb3e`、target-declared
  `aarch64-apple-darwin`、Wasm 6,822 bytes、runtime stdout `41\n1\n7\n`、exit `0`、
  `wasm-tools validate` を確認した。literal record-field pattern は Rust `LS3001` の明示
  unsupported boundaryとして別の invalid fixtureへ分離する。native stage0、Linux x86_64、
  artifact/runtime は Rust oracle で確認した。さらに
  `invalid/record-field-pattern-literal` の `LS3001`（line 8, columns 19–21）、exit `1`、
  artifact absent を Rust report で確認し、producer の multiline `Span` parsing を Rust report
  7 tests で固定した。ftable/import byte parity、resource metrics、native stage0、Linux x86_64 は
  未接続なので R1/M1-03 は `[~]` のまま。

### V4-M1-04 — public command parity

**契約:** `compile`、`build`、`test`、`doc`、`repl`、`lsp --stdio`、`mcp-server`、`install` が、
同じ project root、source、identity、diagnostic/output schema を Rust/native で共有する。

- RED: commandごとに source/file、argv/stdin、interactive state、JSON/text、unknown option/tool、
  external helper不在の fixtureを作る。
- GREEN: native runner の public route を一つずつ接続し、Rust/host fallback と暗黙 network/provider を
  negative test で遮断する。package install は lockfile/module-index/installed path の実成果物で確認する。
- Gate: command-specific focused tests、native Mac、Linux source-file smoke、MCP/LSP protocol relay、
  install/repl/doc artifact cleanup。
- 依存: V4-M1-02、V4-M1-03、既存 `LEGACY-TOOL-01` / `LEGACY-DIAG-01`。

### V4-M1-05 — two-target artifact and rollback gate

**契約:** 同一 source commit の Mac Apple Silicon / Linux x86_64 stage0 と packaged artifact が、
fetch後も version/target/source/payload/Wasm/evidence identity を一致させ、rollback は last-known-good
anchorへ戻れる。

- RED: stale commit、fingerprint mismatch、片側 snapshot、checksum mismatch、relative output、VM copy/
  cleanup failure、owned/shared VM ambiguity を固定する。
- GREEN: producer → package → fetch → source-file smoke → release-smoke → rollback の各 pathを
  task-owned workspace と証跡 manifestへ接続する。provider取得/authは caller boundaryのまま明示する。
- Gate: Mac actual producer/runtime、Linux x86_64 Lima runtime（lockを再利用）、packaged bytes parity、
  rollback negative gate、temporary/VM cleanup audit。
- 依存: v0.3 M3-05-N2/N7/N8/N9、V4-M1-01、`LEGACY-BOOT-01`。

### V4-M1-06 — evidence and release completion audit

**契約:** 各 V4 task の fixture、target、command、artifact digest、runtime result、negative gate、ADR
を一つの evidence indexへ束ね、完了項目だけを TODO から削除する。

- RED: evidence missing、scope mismatch、stale artifact、fallback success、未検証 target、ADR/TODO drift を
  audit fixtureにする。
- GREEN: evidence index と audit script が、requirement scopeと証跡 scopeの不一致を失敗として報告する。
- Gate: docs audit、focused/full tests、Mac/Linux evidence、`HEAD == origin/main`、worktree/temp/VM/cache
  cleanup audit。
- 依存: V4-M1-01〜05。先行して docs-only の設計は可能だが、完了移行は全 evidence 後に限定する。

**現在の verified slice (2026-08-01):**

- `scripts/ci/semantic_fixture_evidence_audit.py` は `v4-m1-06` index の fixture、command、ADR、
  report path、negative gate を検証し、参照された Rust/native report と diff result を再計算する。
  index が宣言する `pass` を信用せず、scope mismatch、stale source/target、report差分、pending boundary
  を fail closed にする。
- index の入力形状は [`v4-m1-06-evidence-index.schema.json`](../../../docs/schemas/v4-m1-06-evidence-index.schema.json)
  に固定し、audit 実装と schema の required field、status、target、negative gate の差分を focused test
  で検出する。
- audit の出力は fixture ごとの diagnostics、exit code、artifact digest/size、runtime result、negative
  gate と、全体の `pass` / `pending` / `mismatch` を固定する。終了値はそれぞれ `0` / `2` / `1` とし、
  pending または mismatch を成功へ昇格させない。
- required negative gate は `fallback-forbidden`、`network-forbidden`、`source-commit-bound`、
  `target-declared` の4つで、全て `pass` の明示値を要求する。安全な project-relative path と ADR の
  regular file も必須とする。
- evidence index の report/comparison/ADR 参照は、各 path component の symlink traversal と
  project root 外への resolve を拒否する。読み取り可能な外部 symlink 先の JSON でも証跡として採用しない。
- evidence index の `task` は fixture matrix の `suite` から導出される task identity と完全一致させる。
  現行 `v4-m1-01` matrix では `V4-M1-03` など別 task のラベルを受け付けない。
- これは index/schema と audit の verified slice であり、実 Mac/Linux target artifact/runtime、
  全 V4 task の evidence、release/rollback は未接続である。したがって V4-M1-06 と Milestone 1 は
  `[~]` のまま保持する。
- 決定記録: [`v0.4 M1-06 evidence index audit ADR`](../../adr/decisions-v0.4-m1-06-evidence-index-audit.md)。
- 実行手順: [`V4 M1 semantic fixture evidence runbook`](../operations/v4-m1-semantic-fixture-evidence.md)。

## 実装順

1. V4-M1-01 の fixture inventory を一つの RED として作る。
2. active worktree と重ならない semantic slice を V4-M1-02 または V4-M1-03 から一つ選ぶ。
3. focused GREEN 後に Rust differential → native Mac → 必要な Linux gate の順に進める。
4. V4-M1-04 の public command は command単位で閉じ、未実装 surface を曖昧に成功させない。
5. V4-M1-05 の heavy target/release は共有 lock/artifactを再利用し、同じ replayを重複起動しない。
6. V4-M1-06 の evidence audit 後に ADRへ移し、TODOの active-onlyを維持する。

## 完了判定

Milestone 1 は、V4-M1-01〜06 の各 requirementについて、Rust oracle、native stage0、Mac、Linux、
artifact/runtime、negative boundary、docs/ADR の scope一致 evidence が揃ったときだけ完了とする。
一つでも provider、ABI、target、public command、rollback、cleanup の evidence が不足する場合は
aggregate を `[~]` とし、次の具体的な RED と blocker を残す。

# L# v0.2 M2-02 — Evidence graph

## 位置づけ

M2-02 は M2-01 の typed node identity を executable contract と観測結果へ接続する
canonical model である。これは `lsharp validate` の command/report 実装ではなく、
後続 surface が lossless に投影できる Rust model を固定する slice である。

## Evidence record

`Evidence` は次を必須の構造として保持する。

- `evidence_id` と subject (`Intent` / `Claim` / `Contract`)
- method (`example` / `case` / `assert` / `property` / `production` / `reference` /
  `proof` / `review`)
- outcome (`pass` / `fail` / `contradicted` / `unknown` / `stale`)
- runner、target、source commit、artifact digest
- cases、seed、generator、shrink path、coverage buckets
- producer、tool version、timestamp の provenance
- independence (`same-author` / `independent-review` / `external-observation`)

execution identity と sampling plan を別の value object に分け、case/seed のない
observational evidence も将来明示的に表現できるようにする。

## Typed edges

edge の endpoint を raw string にせず、M2-01 の ID type で固定する。

```text
Intent       -motivates->       Claim
Claim        -constrained-by->  Assumption
Claim        -tested-by->       Contract
Observation  -supports/contradicts-> Claim
Review       -evaluates->       Intent | Claim | Evidence
Change       -invalidates->     Review | Evidence
```

`EvidenceGraph` は evidence ID の重複と、evidence registry に存在しない evidence を
参照する edge を拒否する。`ExecutionIdentity`、`SamplingPlan`、`Provenance`、
`Evidence` の `validate_required_fields` は required string を空値のまま通さず、
graph への登録も `GraphError::InvalidEvidence` として fail-closed に拒否する。
intent/claim/review/change の project-level registry と全 edge の closure 検査は
M2-03 `validate` へ残す。

## 後続境界

- parser/manifest から evidence record と `supports` / `contradicts` edge を構築する入力
  syntax（source の `motivates` / `constrained-by` / `tested-by` は graph adapter へ接続済み。
  source `:evidence` の required fields と登録済み record への `supports` / `contradicts` 接続も
  Rust adapter へ接続済み。registry 未接続時は明示的に拒否する）
- source `:evidence` の shrinks/coverage、manifest emission、selfhost/native parity
- evidence JSON schema と text/JSON report
- duplicate node、orphan edge、contradiction policy の project validation
- review の author/provenance 認証と privacy/redaction policy

これらは typed model の構造を暗黙に変更せず、個別の RED と observable contract で
追加する。

# L# v0.2 Milestone 1 — Honest executable contracts

## 目的

現行 metadata の checker/parser/runner 間の不一致を閉じ、L# が「何を、どの方法で、何件確認したか」を正直に返す executable contract 基盤を作る。

本 milestone は `Implementation conformance` の信頼できる土台を作る。`Intent validation` graph、semantic diff、SMT/Lean は後続 milestone とし、M1 の完了主張へ混ぜない。

## 最初の RED

`EC-M1-01 invariant parameter scope parity` を最初の縦切りとする。

```lisp
(defn succ [x]
  :invariant (= result (+ x 1))
  (+ x 1))
```

期待値:

- invariant は 1 件
- legacy deterministic sample 5 件すべて pass
- contract scope は `{x, result}`
- Rust oracle と embedded/selfhost が同じ semantic result を返す
- default CLI は exit 0 と `examples:0 / invariants:1 / failures:0` 相当の構造化結果を返す

現状の failure boundary:

- Rust runner: generated invariant scope に `x` がなく型エラー
- selfhost runner: contract 式側の `x` が未束縛で Unit/0 相当となり、0 以外の sample が失敗

RED 候補:

- `test_run_metadata_tests_binds_invariant_parameters`
- `test_embedded_metadata_runner_matches_rust_oracle_for_invariant_parameter_scope`

実装前に両テストの失敗を確認し、期待値を現行 failure に合わせて変更しない。

## Ordered task slices

### EC-M1-01 — invariant parameter scope parity

- RED で元関数引数と `result` の scope を固定する
- Rust runner と selfhost runner の binding を一致させる
- unknown variable の silent Unit/0 fallback を contract path では stable diagnostic にする
- focused Rust/selfhost/embedded tests を green にする

### EC-M1-02 — current semantics inventory and canonical metadata IR

- Rust AST/checker、selfhost parser、formatter、docs、runner の observable matrix を fixture 化する
- `ContractSuite` / `Example` / `Case` / `Assertion` / `Property` の canonical IR を追加する
- source scan/raw text/tag vector から canonical IR への変換を一箇所へ寄せる
- roundtrip と source span preservation を snapshot で固定する

### EC-M1-03 — form separation and migration

- docs-only `:example`、explicit `:case`、Bool `:assert`、sampled `:property` / `:postcondition` を parser/type checker に追加する
- legacy `:example` / `:invariant` の migration classifier を実装する
- ambiguous form は silent conversion せず stable diagnostic を返す
- formatter、docs、schema、MCP surface を同時に更新する

### EC-M1-04 — strict predicate typing and non-vacuity

- assert/property/postcondition を Bool 必須にする
- zero-case、unreachable precondition、constant-true predicate を検出する
- checker と全 runner が同じ diagnostic code/span を返す

### EC-M1-05 — reproducible type-directed sampling

- Int/Bool/String/record/ADT の型指向 generator を追加する
- constraint conjunction に基づく inside/boundary case を生成する
- seed、case count、generator version、shrink path、coverage buckets を保存する
- `legacy-deterministic-smoke` と property profile を明確に区別する

### EC-M1-06 — structured assurance report and CLI boundary

- result schema を `implementation_conformance` と `intent_validation` に分ける
- top-level `verified` を出力しない
- `lsharp test` は conformance だけを判定し、method/cases/seed/coverage/target/provenance を返す
- text/JSON output、exit code、Rust/selfhost result shape を snapshot で固定する

### EC-M1-07 — native parity and migration closure

- verified native stage0 から Mac Apple Silicon で actual test execution を行う
- Linux x86_64 で同じ fixture/result schema/exit code を actual execution する
- Rust oracle differential を実行し、差分 allowlist を空にするか明示理由を残す
- user guide、language reference、schema、migration notes を current behavior に同期する

## Gate matrix

| Gate | 必須 evidence |
|---|---|
| parser/AST | canonical IR roundtrip、全 form の source span |
| type/check | strict Bool、scope、undefined variable、migration diagnostic |
| Rust oracle | case/property execution と structured report |
| embedded/selfhost | Rust oracle と同一 fixture/result/exit code |
| Wasm runtime | generated artifact の validation と standalone execution |
| Mac Apple Silicon | verified native stage0 から actual execution |
| Linux x86_64 | verified native artifact/VM から actual execution |
| docs/schema | guide、reference、JSON schema、MCP output の同期 |

Rust driver の成功、単一 layer test、summary/header の生成だけでは M1 を完了にしない。

## Definition of done

- EC-M1-01〜07 の RED/GREEN 証跡がある
- checker、Rust oracle、embedded/selfhost の observable semantics が一致する
- Mac Apple Silicon と Linux x86_64 の actual artifact/runtime gate が通る
- legacy form の migration path と拒否条件が文書化される
- report は method/cases/seed/coverage/provenance を失わず、assurance 二軸を保持する
- `TODO.md` の M1 task を完了履歴 ADR へ移し、次 milestone を active にする

## 実行上の注意

- TDD を守り、各 task は一つの狭い RED から始める
- Linux VM/stage regeneration は共有 lock と artifact reuse を使い、同じ heavy replay を重複起動しない
- user-owned worktree 差分を巻き戻さない
- unsupported semantics を Rust fallback で成功に見せない

# L# v0.2 M2-03 — Intent validation model

## 位置づけ

この slice は M2-02 graph の事実を assurance report へ写像する判定 model、version 1 JSON
manifest の入力境界、Rust CLI の最小 command surface を固定する。source syntax は node、
required-field evidence record、typed edge までを adapter として接続する。embedded CLI と
optional sampling fields は source adapter から canonical `SamplingPlan` / manifest へ投影済みだが、
selfhost/native parity は先取りしない。
欠落を pass と解釈せず、contradiction と未完了状態を分離する。

## 判定規則

`IntentGraph::validate()` は次を返す。

- `trace_gaps`: intent に claim が紐付かない、または claim に contract test がない
- `open_questions`: graph に残る `OpenQuestion` node 数
- `independent_reviews`: `Review` evidence のうち `IndependentReview` の数
- `contradicting_observations`: `Contradicted` outcome または `contradicts` edge の
  unique evidence 数
- `status`: `pass` / `fail` / `unknown`

status は次の順に決める。

1. contradiction が一つでもあれば `fail`
2. trace gap、open question、独立 review 0 のいずれかがあれば `unknown`
3. それ以外は `pass`

`unknown` は stakeholder intent の妥当性を宣言しないための状態であり、実装
conformance の `test` 結果とは別軸である。top-level `verified` は生成しない。

JSON projection の実装済み shape は
[`intent-validation.schema.json`](../../schemas/intent-validation.schema.json) に固定する。
`ValidationReport::to_json_string()` はこの shape を返すが、入力 parser/CLI が接続する
までは library projection として扱い、Rust model が正本である。

`ValidationReport::to_text()` も JSON と同じ順序・事実を newline-delimited で出力する。
text/JSON のどちらにも `verified` shortcut はない。

graph manifest の出力 shape は
[`intent-graph.schema.json`](../../schemas/intent-graph.schema.json) に固定する。
`IntentGraph::to_manifest_json_string()` は node、evidence、typed edge、execution、
provenance を登録順のまま deterministic に投影する。manifest の事実と
`ValidationReport` の assurance status は別の wire object として保持し、manifest に
`verified` のような policy shortcut は追加しない。

`parse_intent_graph_json()` は同じ version 1 manifest を `IntentGraph` へ戻す。unknown
field、未対応 schema version、重複 node、逆順 span、空の evidence required field、
存在しない node/evidence reference は fail-closed に拒否する。source syntax から
manifest を生成する adapter は別の入力契約として残す。Rust CLI の `--source` mode は
source を直接 graph へ投影する入力境界として追加した。`--emit-manifest` は graph を version 1
manifest file へ atomic/durable に出力する artifact boundary であり、report stdout とは分離する。

## Source node adapter

`lsharp-syntax` は宣言 metadata の次の node form を受理する。

```lisp
:intent "intent:checkout/safe-cancel" "Users can cancel an order"
:claim "claim:checkout/cancel-rejects-shipped" "The API rejects shipped orders"
:assumption "assumption:checkout/state-authoritative" "Shipment state is authoritative"
:open-question "open-question:checkout/cancel-after-label" "Can cancellation happen after a label?"
```

`lsharp_types::validation_source::source_program_to_intent_graph` は wire ID、本文、directive
span をそのまま typed node へ投影する。form kind と wire prefix の不一致、duplicate ID、
invalid/empty node は fail-closed にする。

node metadata と同じ宣言位置では、endpoint を wire ID で明示する次の source edge form も
受理する。

```lisp
:motivates "intent:checkout/safe-cancel" "claim:checkout/cancel-rejects-shipped"
:constrained-by "claim:checkout/cancel-rejects-shipped" "assumption:checkout/state-authoritative"
:tested-by "claim:checkout/cancel-rejects-shipped" "contract:checkout/cancel-case"
:supports "evidence:checkout/cancel-observation" "claim:checkout/cancel-rejects-shipped"
:contradicts "evidence:checkout/cancel-counterexample" "claim:checkout/cancel-rejects-shipped"
```

evidence record は edge と同じ宣言位置で次の named fields を明示する。

```lisp
:evidence "evidence:checkout/cancel-observation"
  :subject "claim:checkout/cancel-rejects-shipped"
  :method "case" :outcome "pass"
  :runner "cargo-test" :target "aarch64-apple-darwin"
  :source-commit "0123456789abcdef" :artifact-digest "sha256:abc123"
  :cases 1 :seed 42 :generator "checkout-cancel-fixture"
  :producer "lsharp-test" :tool-version "0.2.0"
  :timestamp "2026-07-25T00:00:00Z" :independence "same-author"
```

adapter は node registry を先に構築してから edge を解決し、typed endpoint の kind mismatch
と orphan reference を fail-closed に拒否する。`:tested-by` は Claim と Contract の wire ID を
typed edge へ投影し、claim の trace gap を閉じる。`:supports` / `:contradicts` は Observation の
`EvidenceId` と Claim の `ClaimId` を検証し、登録済み evidence のみ graph edge へ投影する。
registry が未接続の間は `EvidenceRegistryRequired` の入力エラーとして fail-closed に拒否する。
Contract の executable definition、selfhost/native parity は未接続である。Rust CLI の
`--emit-manifest` atomic/durable file emission は接続済みだが、release provenance と selfhost producer は未接続である。

Rust CLI の `lsharp validate [<manifest>] [--format text|json]` は parser → graph →
`validate()` → report を接続する。source を直接検証する場合は
`lsharp validate --source <source.ls> [--format text|json]` を使い、source parser と
`validation_source` adapter を同じ report path へ接続する。`--source` と positional
manifest は同時指定しない。manifest を省略した場合は project root の `lsharp.toml` にある
`[validation].manifest` を project-relative に解決する。絶対 path、親 traversal、存在しない
file、project root 外の symlink は拒否し、設定も明示 path もない場合は暗黙の既定値を使わず
診断する。source は evidence record 未接続なら `unknown` を返し、parse/adapter error は
report status と混ぜずに入力診断として返す。`pass=0`、`fail=1`、`unknown=2` の exit code
を返す。

## 後続境界

- source node/edge から version 1 manifest/evidence を生成する adapter（project config による
  JSON manifest 発見、node registry、`motivates`/`constrained-by`/`tested-by`、Rust
  `validate --source` の graph/report 接続、required-field evidence record、
  `supports`/`contradicts` の registry-required fail-closed boundary、`--emit-manifest` の Rust atomic/durable file output は実装済み）
- source syntax 側の selfhost/native sampling parity、duplicate ID / orphan
  edge を selfhost/native でも共有する入力診断 policy
- selfhost/native の manifest parser、report、exit code parity
- MCP/embedded CLI への command wiring と target 別 artifact/runtime evidence

これらはこの判定 model を再利用し、別の RED で固定する。

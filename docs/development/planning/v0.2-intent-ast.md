# L# v0.2 M2-01 — Intent AST と stable ID

## 位置づけ

M2-01 の最初の実装 slice は、parser や `validate` command へ接続する前の
canonical model を固定する。source syntax は node registry と node-to-node edge までを
別 adapter として接続し、evidence edge は後続タスクで追加する。この model の wire contract
は変更しない。

## Node model

`lsharp_types::intent::IntentNode` は次の 4 種類を保持する。

| node | 意味 | ID type |
| --- | --- | --- |
| `Intent` | 誰のどの目的を満たすか | `IntentId` |
| `Claim` | 何が真だと主張するか | `ClaimId` |
| `Assumption` | 主張が依存する前提 | `AssumptionId` |
| `OpenQuestion` | 未決定または未検証の問い | `OpenQuestionId` |

各 node は `id`、`text`、`source_span` を持つ。edge、evidence、review、provenance
は M2-02 で別の型として追加し、node 自体へ混ぜない。

## Stable ID contract

ID の wire value は次の形式である。

```text
kind:namespace/key
```

graph の wire kind は `intent` / `claim` / `assumption` / `open-question` /
`contract` / `evidence` / `review` / `change` のいずれかで、`namespace` と `key` は
空でない ASCII の `[A-Za-z0-9_.-]` segment とする。AST node として保持するのは前半の
4 種類だが、後半は evidence edge の typed subject identity に使う。
たとえば `IntentId::new("checkout", "payment-success")` は
`intent:checkout/payment-success` になる。

この ID は source span、宣言順、Rust の hash、target、formatter の出力に依存しない。
従って同じ namespace/key を持つ Rust/selfhost projection は同じ文字列を返し、
宣言の移動や整形で evidence の subject identity が変わらない。node kind を wire
prefix に含めるため、同じ namespace/key の intent と claim は衝突しない。

`StableId::parse` は `kind:namespace/key` を同じ segment 検証付きで復元する。各 typed ID
の `parse` は wire prefix と宣言された kind の一致も検査するため、unknown kind、separator
欠落、余分な segment、typed kind mismatch は fail-closed に拒否する。これにより source
link、manifest、Rust/selfhost の各 adapter が raw string を個別に解釈せず同じ identity
contract を再利用できる。

source/manifest adapter が wire identity、説明文、source span を同じ境界で AST へ投影
できるよう、`IntentNode::from_wire_parts` を用意する。この変換は 4 種類の typed AST
 node だけを構築し、`contract` / `evidence` / `review` / `change` は graph-only kind
 として明示的に拒否する。空 text と不正 wire はそれぞれ `NodeTextError` /
 `StableIdError` を保持したまま返し、adapter ごとの暗黙変換を許さない。

## Source node syntax (current slice)

宣言の metadata 位置に、stable ID の wire value と本文を明示する。

```lisp
(defn cancel []
  :intent "intent:checkout/safe-cancel" "Users can cancel an order"
  :claim "claim:checkout/cancel-rejects-shipped" "The API rejects shipped orders"
  true)
```

`:assumption` と `:open-question` も同じ形式で記述できる。4 種類の form は source order と
directive span を保持したまま `IntentNode` へ投影する。wire prefix と form kind が異なる場合、
本文や ID が空の場合、同じ ID が複数回現れる場合は暗黙に補正せず拒否する。node form と同じ
metadata 位置では、`:motivates`、`:constrained-by`、`:tested-by` の typed edge も wire ID 二つで
記述でき、adapter は node 宣言を集めた後に endpoint kind と存在を検査する。Contract の実体や
evidence record は別入力境界であり、`:supports` / `:contradicts` は evidence ID と Claim endpoint を
検証した後、registry 未接続を明示的に診断する。source graph だけで `validate` の `pass` を宣言することはない。

## 明示的に後続へ残す境界

- source node から project manifest / evidence record と evidence edge (`supports`, `contradicts` など) を構築する規則
- source 内で明示 ID を省略した場合の命名解決
- duplicate ID の project-level validation
- `lsharp validate` の report/exit code

これらを stable ID の導出へ暗黙に混ぜず、M2-02/M2-03 の observable contract として
別タスク化する。

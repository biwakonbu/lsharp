# TODO 未完了タスク並列実装 - 要件定義書

> 最終更新: 2026-03-23

## 概要

TODO.md の未完了タスク 12 件を洗い出し、依存関係を分析した上で並列実行可能なグルーピングにより効率的に実装を進める。全タスクは TDD ワークフローに従い、区切りごとに git commit する。3 フェーズ構成で実施し、フェーズ 1-2 の 10 タスクが完了済み。フェーズ 3 (P8-5 stage1 統合) はコンパイラ制限解消が前提のため次イテレーションに繰り越し。

## 機能要件

### 必須機能

#### フェーズ 1: 独立タスク + セルフホスト比較テスト (並列実行)

**グループ A: 完全独立タスク (4 件並列)**

- **FR-001**: P9-2 LSP 定義ジャンプ
  - `textDocument/definition` ハンドラを `lsharp-lsp` に追加し、シンボルの定義位置へのジャンプを実現する

- **FR-002**: P7 stdlib コンパイル・テスト自動化
  - stdlib/ 全 9 モジュール (Char, Core, Debug, IO, List, Map, Set, String, Vector) の E2E テストを追加する

- **FR-003**: R-S1 エラー型統一 (thiserror)
  - 全クレートのエラー型 (LexError, ParseError, InferError, ConstraintError, LowerError, CodegenError, ModuleGraphError) を統一エラー enum でラッピングする

- **FR-004**: R-S6 RefCell 見直し
  - `lsharp-ir/lower/mod.rs` の `string_data`, `lifted_functions`, `lifted_func_indices` の RefCell 使用を構造リファクタリングで解消する

**グループ B: セルフホスト比較テスト (4 件並列)**

- **FR-005**: P8-1 Lexer 比較テスト
  - 同一入力に対して L# Lexer と Rust Lexer の出力が一致するかを検証するテストを追加する

- **FR-006**: P8-2 Parser 比較テスト
  - 同一入力に対して L# Parser と Rust Parser の出力が一致するかを検証するテストを追加する

- **FR-007**: P8-3 型推論比較テスト
  - 同一入力に対して L# 型推論と Rust 型推論の出力が一致するかを検証するテストを追加する

- **FR-008**: P8-4 Codegen 比較テスト
  - 同一入力に対して L# Codegen と Rust Codegen の出力が一致するかを検証するテストを追加する

#### フェーズ 2: 依存ありタスク

- **FR-009**: P2-3 HashMap 文字列キー対応
  - FNV-1a ハッシュ関数を Wasm ヘルパーとして実装し、文字列キーによるハッシュマップ操作を可能にする (data section ベースで実装)

- **FR-010**: P3-3 :invariant/:example 実行評価
  - `generate_tests()` が生成したテストを compile_and_run パイプラインに通し、実行結果を検証する機能を追加する

#### フェーズ 3: ブートストラップ (次イテレーションに繰り越し)

- **FR-011**: P8-5 stage1 統合
  - セルフホスト 9 モジュールをモジュールリンカーで結合し、stage1 コンパイラとして動作させる
  - 現在スキップ中の 3 モジュール (Lexer.ls, Parser.ls, TypeScheme.ls) のコンパイラ制限を解消する

### 保留 (対象外)

- **FR-DEF-001**: P1-2 文字列リテラルのヒープ化
  - 破壊的変更のため本スコープから除外。現行の data section ベースで他タスクは進行可能

## 非機能要件

### 開発プロセス

- **NFR-PROC-001**: 全タスクで TDD ワークフロー (RED -> GREEN -> REFACTOR) を遵守する
- **NFR-PROC-002**: 各フェーズ完了時、または論理的な区切りで git commit する
- **NFR-PROC-003**: テスト 0 件の項目は TODO.md で `[x]` にしない (`[~]` で留める)

### 品質

- **NFR-QUAL-001**: 既存の E2E テスト (e2e.rs) が全てパスし続けること (回帰なし)
- **NFR-QUAL-002**: `cargo clippy` で新規警告を出さないこと

### 保守性

- **NFR-MAINT-001**: 既存のコーディング規約 (snake_case for Rust, kebab-case for L#) に従う
- **NFR-MAINT-002**: 1 ファイルあたり 500-800 行の制限を遵守する

## 制約条件

- **CON-001**: P8-5 stage1 統合はコンパイラ本体の制限 (相互再帰関数の前方参照未対応、深いネスト if のパースエラー) の解消が前提
- **CON-002**: P1-2 文字列ヒープ化は本スコープでは着手しない
- **CON-003**: P2-3 HashMap 文字列キーは P1-2 なしで data section ベースの workaround で実装する

## 受入条件

- **AC-001**: フェーズ 1 完了時に、グループ A + B の 8 タスクそれぞれに対応するテストが追加されパスしていること
- **AC-002**: フェーズ 2 完了時に、HashMap 文字列キーと invariant/example 実行がテスト付きで動作すること
- **AC-003**: フェーズ 3 完了時に、stage1 統合テストで 9 モジュール全てがコンパイル・リンクできること (制限解消含む)
- **AC-004**: 全フェーズ通じて既存テストの回帰がないこと (`cargo test` 全件パス)
- **AC-005**: TODO.md の完了タスクが `[x]` マークに更新され、テスト数が注記されていること

- パフォーマンス最適化

# workspace の既知 FAIL 一覧 (ISSUES.md I-11 の正本)
#
# 書式: 1 行 1 test。`<binary-id> <test-name>` の 2 語。`#` 以降は注記。
# binary-id は必須。同名 test が複数 binary に現れる (tests/e2e/support.rs の
# `mod` 共有など) ため、test 名だけでは同一性が決まらない。
#
# 検証: scripts/ci/check-workspace-baseline.sh
#   - ここに無い FAIL が出たら非 0 (新規 regression)
#   - ここに有る test が pass に転じても非 0 (baseline の更新漏れ)
#   - ここに有る test が実測に現れなくても非 0 (rename / 削除の追随漏れ)
#
# 測定環境の前提 (これが変わると集合が変わる):
#   - リポジトリ root に `./stage0` が **無い** こと。fresh clone と CI の既定状態。
#     `./stage0` があると selfhost_native_stage_chain / selfhost_native_stage23_gap の
#     成否が変わる。
#   - 測定は `cargo nextest run --workspace --profile baseline` (.config/nextest.toml)。
#   - doctest は nextest の対象外。`cargo test --doc` は別途 1 回回して結果を注記する。
#   - `scripts/ci/test-*.sh` の shell 契約テストはこのリストの対象外 (別枠で管理)。

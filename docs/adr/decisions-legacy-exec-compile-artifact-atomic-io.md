# ADR: compile pipeline の Wasm artifact atomic I/O

- Status: Accepted (verified partial slice)
- Date: 2026-07-24
- Scope: `compile_file` / Preview1 `.wasm` / Preview2 `.component.wasm` / WebWasm `.wasm`

## Context

CLI Component の artifact 保存に atomic replacement を導入しても、通常の `compile_file` は
Preview1、Preview2 Component、WebWasm の bytes を直接 `std::fs::write` していた。この経路は
生成途中の bytes を destination に公開し得るため、Component 以外の Wasm artifact でも保存契約を
統一する必要がある。一方、Native executable は linker が扱う別成果物であり、同じ API へ暗黙に
含めると失敗境界を曖昧にする。

## Decision

- `lsharp_wasm::component_adapter::write_wasm_artifact` を Component に限定しない共有 Wasm artifact
  writer とする。親 directory の process-unique temporary path へ書込み、成功時だけ `rename` する。
- `read_wasm_artifact` は保存済み bytes を明示的に再読込する。既存の Component 専用 API は互換 wrapper
  として残す。
- `lsharp_tooling::compile::write_compile_artifact` を compile pipeline の単一入口とし、
  `WasiPreview1`、`WasiComponent`、`WebWasm` の output write をこの入口へ通す。Native は別境界のまま
  維持する。

## Evidence

- Unit test: `compile::tests::test_compile_artifact_writer_uses_atomic_wasm_boundary`
- API tests: `component_adapter::tests::test_wasm_artifact_round_trip_supports_non_component_output`
  / `test_component_artifact_round_trip_replaces_without_temp_residue`
- Existing compile target tests continue to validate generated bytes and runtime behavior.

## Residual risk

この ADR は Wasm artifact の atomic write/read と compile pipeline 3 target の接続を閉じた verified
partial slice である。durable fsync、source fingerprint/manifest、Native executable release、Mac
Apple Silicon/Linux x86_64 native stage0、selfhost parity、rollback provenance は未完了である。

# ADR: Linux x86 int-to-string bounded heap allocation

- Date: 2026-08-02
- Status: accepted for the verified slice
- Related: `V2-16e`, `V2-13a-5`, `LEGACY-BOOT-01`

## Context

The Linux x86 selfhost `int-to-string` helper allocated a fixed 32-byte
String object with one `mmap` syscall per conversion. The helper is used by
diagnostics and code materialization, so the syscall path added working-set
pressure to the current-source stage2 boundary. The existing signed i64
conversion, String header, payload copy, high-bit tag, and import-6 ABI must
remain unchanged.

## Decision

Use the materializer-owned `r14` native heap. Treat `(%r14)` as a cursor
offset and `8(%r14)` as the exclusive limit. A zero cursor uses the existing
data frontier `8192` in a register. The helper checks `cursor + 32 <= limit`
before writing the cursor, then converts the cursor to an object address by
adding `r14`. Failure returns zero without changing the cursor. `rbx` and
`r14` remain callee-saved. The generated helper is 160 bytes; its trailer
start remains `base + 2219` because the helper is last.

## Evidence

RED:

- `test_native_codegen_x86_int_to_string_uses_bounded_heap_cursor` detected
  the old `48 c7 c0 09 00 00 00 0f 05` (`mov rax,9; syscall`) sequence.

GREEN:

- The focused no-mmap test and the existing signed decimal/header ABI test
  passed with the 160-byte helper.
- The source-generated byte vector and a clang-assembled Linux object were
  byte-for-byte identical.
- A minimal Linux x86_64 Lima program initialized an `r14` heap and printed
  `-42` from the generated helper.
- The same VM-side lock and generated helper verified the `+31` limit failure
  leaves the cursor unchanged and the `+32` limit succeeds.

## Boundary

This closes only the signed int-to-string bounded allocation and limit
boundary. It does not prove full current-source stage2/stage3 transport,
materialization, fixed-point parity, Linux stage0 source-file smoke, package
acquisition/release/rollback, the remaining `substring`/`read-file` allocation
contracts, or Mac/Linux release parity. Those remain `[~]` under `TODO.md`.
